## What carries over to Mini 2

Internal-root boot is now a plausible A7 development path. It is not yet a
qualified J86 path. J72 is Air 1 Cellular (`iPad4,2`), while our measured board is
J86 (`iPad4,5`). J85 Wi-Fi (`iPad4,4`) and J86m (`iPad4,6`) require their own
identity, DT, firmware and storage checks. Shared A7 silicon does not justify
copying board addresses, firmware reservations, calibration or partition offsets.

Separate three questions: can ASP read the correct namespace; can early Linux
resolve the intended root; and can that filesystem be written durably? A UUID
link fix addresses only the second. Internal root also does not remove the
checkm8/Pongo boot chain or establish power-on boot without a host.

Before adapting ASP, obtain the actual current J72 source and review its license,
loader/firmware handoff, exact J86 DT registers/IRQs/clocks, reserved no-map DMA
memory and timeout/retained-buffer rules. Start with a manually enabled read-only
observer, with writes/unlock/flush/discard and auxiliary namespaces excluded at
submission. Validate geometry, bounded repeated reads and both complete GPT
copies before interpreting partitions. Do not auto-mount or replay APFS journals.

For UUID handling, inspect the captured root selector and filesystem signature,
then early-boot udev rules for ASP disk/partition naming. Check whether blkid runs
and `/dev/disk/by-uuid` (filesystem UUID) or `/dev/disk/by-partuuid` (GPT partition
UUID) links appear before root lookup. Match links to the exact intended device;
reject missing/duplicate IDs rather than choosing the first disk. Never substitute
APFS container/volume IDs for ext4 UUIDs or GPT PARTUUIDs. Any eventual rule must
handle the measured ASP naming convention, trigger at the right boot stage and
preserve existing disk rules; do not fabricate links from a guessed `/dev/asp*`.

The new [offline audit](../storage/root-identity-audit.py) compares **saved host
files** containing `blkid -o export` output and fstab. It distinguishes UUID from
PARTUUID, rejects ambiguous identities and APFS as a candidate Linux root. It
never runs blkid, connects to the iPad, creates symlinks, mounts, writes storage
or enables an installer. A passing report is not live UUID-link qualification.

```
python3 storage/root-identity-audit.py --blkid-export saved-blkid.txt --fstab saved-fstab.txt
```

Keep real identifiers and metadata captures private. Do not collect them by
loading an unreviewed storage driver. Synthetic test fixtures contain no real IDs.

## Storage safety gate

**Resizing APFS or deleting snapshots can destroy iOS/data or make recovery
necessary. Back up first**, verify that the backup is usable, and agree on a
recovery route before proposing a concrete layout. Free space inside APFS is not
an unallocated partition gap and is not the supported shrink minimum. Do not
reuse Cam's 50 GB number or remove a rollback snapshot as routine preparation.

Perry must explicitly approve the specific plan before snapshot deletion, APFS
resize, GPT changes, formatting, filesystem installation, write qualification or
any other internal-storage write. Previous general interest in replacing iOS is
not approval of a new destructive procedure. Even after approval, keep RAM boot
available and qualify bounded writes, flush/durability and recovery before a
writable internal root. This checkpoint adds no installer, ASP driver or boot
configuration changes.
